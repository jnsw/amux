# UX/Design Review — amux Redesign (2026-05-14)

## TL;DR

The redesign shows real polish: the theme system is genuinely good, the Cmd+K palette is there, and the session-card hierarchy is clean. The critical gap is that half the tab surface is a legacy iframe passthrough — two thirds of the sidebar's navigation items open unrestyled old HTML inside the new shell, which destroys every visual promise the redesign makes. Secondary blockers: the peek panel defaults to fullscreen-always and auto-scrolls with no way to pause; multiple destructive actions still use `window.confirm()` / `window.prompt()` instead of inline UI; and the "open full transcript in legacy view" escape-hatch is a permanent fixture rather than a transitional one.

---

## P0 — Critical Findings (UX breaks or confuses)

### P0-1: Legacy iframe swallows ~80% of navigation destinations
- **Where:** `secondary.jsx:120-131` (`LegacyEmbed`), `app.jsx:113-126` (all `renderTab` cases except `sessions` and `settings`)
- **What:** Board, Calendar, Scheduler, Files, Notes, Logs, Metrics, Terminal, Browser, CRM, Map, Habits, Torrents, Journal, Graph — all render as `<iframe src="/legacy?view=…&embedded=1">`. The new shell chrome (sidebar, workspace tabs, themes) wraps old, unstyled HTML that ignores every design token. Users switching from Sessions to Files land in a visually different application.
- **Why bad:** Nielsen #4 (Consistency). The redesign's value proposition collapses the moment someone clicks a second tab. Mixed-fidelity UIs train users to distrust the interface.
- **Fix:** Either (a) gate those tabs behind a clear "Legacy / Beta" label and deliberately show a migration roadmap empty-state instead of a silent iframe, or (b) block them from appearing in the sidebar until the native tab is built. The current approach makes the redesign look broken to a new user.

### P0-2: Permanent "open full transcript in legacy view" links in critical paths
- **Where:** `peek.jsx:503`, `tweaks.jsx:403` (About card, "open legacy view ↗")
- **What:** Hardcoded anchor tags to `/legacy` sit inside the Output tab of the peek panel and the About section of Settings. Both will exist forever unless someone remembers to remove them.
- **Why bad:** Nielsen #8 (Aesthetic / Minimalist). A link that says "this redesign is not complete" undermines trust. The one in peek.jsx is especially damaging — it is the first visible action after the transcript and teaches users the redesign is a dead end.
- **Fix:** Add a `TODO(cutover)` comment block and gate them behind `window.AMUX_LEGACY_FALLBACK` or remove them entirely. The transcript link is unnecessary because a copy-all button already exists at `peek.jsx:442`.

### P0-3: `window.prompt()` / `window.confirm()` for destructive and input actions
- **Where:** `sessions.jsx:49` (Rename), `sessions.jsx:59` (Change model), `sessions.jsx:78` (Edit description), `sessions.jsx:89` (Edit tags), `sessions.jsx:101` (Change directory), `sessions.jsx:162` (Delete with `confirm()`)
- **What:** Six actions in the MoreMenu open native browser dialogs. On mobile these are full-screen takeovers with no styling; on desktop they break the visual context, block the thread, and cannot be dismissed with the app's own Escape handler.
- **Why bad:** Nielsen #4 (Consistency), Nielsen #3 (User Control). FRONTEND-SPEC.md §2.2 already mandates "Kein `window.prompt()` mehr." The spec says it, the code ignores it.
- **Fix:** Inline editable fields or a small sheet/popover per action. Rename is the most common — a click-to-edit `<input>` on the card name (like Linear) takes 20 lines and is 10× better.

## P1 — Important Improvements

### P1-1: Auto-scroll in peek output has no pause affordance
- **Where:** `peek.jsx:259-266` (unconditional `scrollTop = scrollHeight` on every `ccHTML` change)
- **What:** Every new line of transcript output snaps the view to the bottom. If a user scrolls up to re-read something, the next SSE tick immediately yanks them back down. There is no "tailing paused / click to resume" indicator.
- **Why bad:** Nielsen #3 (User Control and Freedom). Warp, VS Code integrated terminal, and every serious log viewer have a "pause tail" mode triggered automatically when the user scrolls up.
- **Fix:** Track whether the scroll container is within ~50px of the bottom. If not, suppress auto-scroll and show a "↓ New output" pill (click to jump + resume). ~30 lines of logic, high impact.

### P1-2: QuickKeys touch targets are 26px — below iOS minimum
- **Where:** `app.css:735` (`.qkey { --qk-h: 26px }`)
- **What:** The entire QuickKeys row renders at 26px height. The `.claude/rules/css-mobile.md` rule in the repo itself says "Touch targets must be at least 44x44 on mobile."
- **Why bad:** Violates the project's own stated constraint. On a 375px iPhone the row becomes nearly untappable, and it is the primary interaction surface inside the Peek panel.
- **Fix:** `--qk-h: 36px` on desktop, `--qk-h: 44px` under `@media (hover: none)`. The extra height can be absorbed by reducing the gap or using a smaller font.

### P1-3: Peek panel opens as fullscreen by default — blocks context
- **Where:** `peek.jsx:183` (`const [fullscreen, setFullscreen] = useStateP(true)`)
- **What:** Selecting any session immediately takes over the entire content area (minus sidebar). On a 13" MacBook this hides all session cards, making it impossible to compare two sessions at a glance or drag-switch without hunting the sider.
- **Why bad:** Nielsen #3 (User Control). The peek panel's original design intent was a 440px right-panel drawer (`app.css:378`). Fullscreen should be an explicit escalation, not the default. The peek sider inside fullscreen mode (a scrollable list of sessions) is a band-aid for the problem the fullscreen default created.
- **Fix:** Default `fullscreen` to `false`. Let users escalate to fullscreen via the existing "Expand" button. Persist the preference in AppTweaks.

### P1-4: Delete action uses `window.confirm()` — no undo path
- **Where:** `sessions.jsx:162-165`
- **What:** Delete is the only action with a confirmation dialog, but it uses `window.confirm()` (blocking, unstyled) and there is no undo/restore option. Archive exists as a separate action but is not surfaced as an alternative in the delete flow.
- **Why bad:** Linear-Method pattern: prefer undo-toasts over confirm dialogs. The modal is worse UX than a toast with a timed "Undo" button.
- **Fix:** Remove `confirm()`. Issue `DELETE` immediately, show a toast with a ~5s "Undo" button that calls a `POST /api/sessions/<name>/restore`. This matches what Vercel, Linear, and Notion all do.

### P1-5: Filter bar has two non-functional provider chips
- **Where:** `sessions.jsx:356-358`
- **What:** "claude" and "codex" provider filter chips are rendered but have no `aria-pressed` state, no `onClick`, and no filtering logic. They look interactive but do nothing.
- **Why bad:** Nielsen #1 (Visibility of System Status), Nielsen #10 (Help Users Recognize). Broken affordances erode trust faster than missing features.
- **Fix:** Wire them to a `provider` filter state, or remove them until the feature is real. The empty `onClick` is worse than absence.

### P1-6: Search in peek only matches `s.preview` (last 8 lines), not full output
- **Where:** `peek.jsx:268-275` (`matches` computed from `s.preview.reduce(…)`)
- **What:** The in-panel search (`S` to open) searches `s.preview` — the short ring buffer shown on cards — not `fullOutput`, which is what the user is actually looking at in the Output tab. Searching for a function name that appeared 200 lines ago returns 0 matches even though the transcript is fully rendered.
- **Why bad:** Nielsen #1 (Visibility of System Status). The "0/0" indicator gives no indication that the search is scoped incorrectly.
- **Fix:** Run `matches` against the already-rendered `fullOutput` string (split by `\n`), not `s.preview`. The data is already in component state.

## P2 — Nice to Have

### P2-1: No unread / "new activity" indicator per session card
- **Where:** `sessions.jsx` — no badge or dot indicating sessions with new output since last peek open
- **What:** With 10+ sessions running concurrently, the user has no way to see which ones have produced new output without opening each one.
- **Fix:** Track a `lastSeenBump` in AppTweaks or component state. Render a subtle accent dot on cards where `s.previewBump > lastSeenBump[s.name]`.

### P2-2: Cmd+K palette "hint" column shows navigation sequence strings (e.g. "G then S") but those sequences are not implemented
- **Where:** `palette.jsx:24-31`
- **What:** Navigation items show hints like "G then S" (go to Sessions) — a Vim/Linear-style chord. But no keydown handler implements g-then-S navigation. Users who try this after reading the hint get nothing.
- **Fix:** Either implement g-mode (`g` arms a mode, second key dispatches to tab) or replace hints with empty strings until the chords exist.

### P2-3: Board tab minimum width hard-coded at 1100px — unusable on smaller screens
- **Where:** `secondary.jsx:50` (`minWidth: 1100`)
- **What:** The board grid requires 1100px minimum. On a 1280px laptop with the sidebar open that leaves ~80px of lateral scroll. No horizontal scroll affordance exists (scrollbar hidden).
- **Fix:** Reduce column `minmax(220px, 1fr)` to `minmax(180px, 1fr)` and let the grid collapse to 3 columns on narrower viewports with a `min-width: unset` breakpoint override.

### P2-4: Settings page has no "Save" feedback for theme/layout toggles — instant apply is silent
- **Where:** `tweaks.jsx:260-301` (all `SetSelect` / `SetToggle` onChange handlers)
- **What:** Toggling theme, density, or nav mode changes are applied instantly and silently. There is no visual confirmation that the change persisted to localStorage vs. just the current render.
- **Fix:** A brief 1.5s toast "Settings saved" on `setTweak` is enough. The current silence is fine for power users; it confuses new users.

### P2-5: "Info" action in MoreMenu dumps raw JSON into a toast
- **Where:** `sessions.jsx:34-36`
- **What:** The Info action shows `JSON.stringify(s._raw).slice(0, 120)` in a toast. This is a developer tool surfaced to all users.
- **Fix:** Either remove it from the default MoreMenu and put it in DevTools (Settings → Developer Tools), or show a proper Session Details modal with structured fields.

## Strengths (what works)

- **Theme system is excellent.** 6 themes × light/dark × 4 accents × 3 densities, all driven by CSS custom properties with zero layout shift. The `data-theme` / `data-light` attribute approach is clean and extensible. The Phosphor green theme in particular looks distinctive and differentiates amux visually.
- **Command Palette (Cmd+K) is fully functional.** Keyboard navigation, grouped results, session fuzzy-search, and escape handling all work correctly. This is the single most important power-user feature and it is done well.
- **QuickKeys armed-state UX is novel and correct.** The two-click-to-send pattern for /cmd buttons (first click inserts + arms, second click sends directly) is a thoughtful solution to the "fat finger sends wrong command" problem. The animated overlay chip communicates the armed state clearly.
- **Empty states are actionable.** The empty session grid shows an explanation and a "New session" CTA button. This is textbook Refactoring UI empty-state-as-onboarding.
- **Skeleton CSS is present.** `is-skeleton` class with `.skel` pseudo-elements exists in the CSS (`app.css:1071-1074`), showing intent to handle loading states properly.

## Comparison to Best-of-Breed

- **vs Cursor:** Cursor's panel model (editor + AI chat side-by-side) is roughly analogous to Sessions + Peek. Cursor never makes the chat panel full-screen by default — it is a 30% sidebar that expands on demand. amux's default-fullscreen peek loses the sessions overview unnecessarily. Cursor also has Cmd+K but adds Cmd+L for chat focus — amux has no equivalent quick-focus shortcut for the composer.
- **vs Zed:** Zed's multi-buffer tabs map to amux's workspace tabs — both are browser-tab-style at the top. Zed keeps the tab count low (≤5 is idiomatic). amux exposes 15+ navigation items in the sidebar, most of which are iframes, making the sidebar feel like a navigation dump rather than a curated workspace. Zed's rule: surface what exists, not what is planned.
- **vs Linear (web patterns):** Linear uses Undo toasts for every destructive action (issue delete, status change) without confirmation dialogs. amux uses `window.confirm()` for Delete and `window.prompt()` for six inline edits — the exact anti-pattern Linear replaced years ago. Linear also shows unread counts per view; amux has no unread state at all.

## Top-3 Next Steps

1. **Kill `window.prompt()` / `window.confirm()` in MoreMenu** (`sessions.jsx:49-165`). Replace Rename, Description, Tags, Directory with a single `<EditRow>` sheet component. Replace Delete confirm with an undo-toast pattern. This is ~1 day of work and removes the single most regressive interaction in the redesign.

2. **Fix auto-scroll in Output tab** (`peek.jsx:259-266`). Add a "pause when user scrolls up" flag and a "↓ New output" resume pill. Without this, the transcript is read-only in practice — any attempt to review previous output is immediately disrupted. This is ~30 lines and makes the core use case (reading what Claude is doing) actually usable.

3. **Gate legacy-iframe tabs with an honest UI state.** Replace the silent `<LegacyEmbed>` fallback for non-implemented tabs with a `ComingSoon` variant that is explicit ("This tab is being redesigned — use the legacy view for now: [link]"). This is honest, reduces the jarring context-switch, and makes the migration roadmap visible to users rather than hidden in INTEGRATION.md.
